## Event Planning Platform

Our project is an class, office hours, and conference scheduling platform for professors and students at Dawson College. 

### Client Profile

- Dawson College

#### Staff/Users Profile

- Professors at Dawson College
- Students at Dawson College

### Types of Events

- Classes
- Office Hours
- Conferences

### Event Resources

- Classrooms / Conference Rooms
- Professor Departments
- Desks
- Laptops
- Semester
- Conference

### Extra Features

-	Collaboration between teachers to share a room (showcasing student work)
-	Signing students in particular class to conference event.
-	Students can login and book office hours from teacher’s available time.
-	Teachers can reserve laptops from the Comp Sci department.

### FAQ

- Can a student request office hours from a teacher outside of their posted office hours?
    - Yes, students can request office hours, but professors are not obligated to approve the request.
- Can a teacher modify their office hours availablity at any time, or only at the start of a semester?
    - Teachers can add new office hours, but not delete already define office hours.
- Can a student not belonging to a class of a particular teacher book office hours with said teacher?
    - Yes.
- Can multiple students book the same office hour of a teacher? (Ex: If they are working on a group project together)
    - Yes.
- Can a professor request office hours with a particular student?
    - Yes, but the student is not obligated to attend.
- Can a professor assign all the students of a class to a particular conference room?
    - Yes they can.

### Questions

1. What will we do to ensure our code is readable?
    - Good variable naming.
    - Good method headers.
    - Good documentation comments.
2. What procedure will we put in place to ensure commited code is functional?
    - Run unit tests and ensure they all pass before pushing.
    - Ensure the code compiles and runs.
3. How do we plan to test our code?
    - Rigorous unit testing for all potential features/situations.
4. How do we plan to divide the work?
    - Utilize gitlab issues to manage who does what.
    - Plan in advance (make skeleton of the project/UML diagram).
    - If anything ends up taking longer than expect, we can divide accordingly.
5. How will we ensure that our application is robust and does not fail due to user errors?
    - Ensure we have unit tests for exceptions that could be thrown.
    - Let our family and friends test our program.
    - Using try catchs and exception handling when necessary.
    - Use while loops to allow user input retry.
6. How will we ensure we have stand alone classes that can be tested?
    - Black box testing (white the unit tests in advance).
    - Utilize design patterns to ensure classes are stand alone.
7. Are there any other guidelines or expectations that we would like to ask one another?
    - What is the expected response time? 
        - 12 hours (within reason)
    - How many labs do you expect to miss?
        - 1-2 maximum

        - Discord group chat
